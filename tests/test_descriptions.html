Live evidence base. These descriptions were written against measurements from six real Vento Expert fans on 192.168.29.0/24 (4× unit type 3 A50-1/A85-1/A100-1 W V.2, 2× type 4 Duo A30-1 W V.2, firmware 0.4), using the Blauberg Smart Home connection guide (B133-4-1EN-02) as the protocol source of truth. Key measured facts:
  • FUNC 0x02 writes never get a response; FUNC 0x03 writes get a 0x06 echo ack whose values equal the applied state (clamping proven: write 30 → echo 40).
  • Negative acks use the 0xFD special command (e.g. fd 90) in reads and writes alike.
  • ~3% UDP loss measured (2 silent responses in ~70 round trips) → retries are mandatory.
  • Wrong password, unknown FUNC, corrupted checksum and device-off are all silent — indistinguishable.
  • A 0x03 write to a write-only param (RESET_ALARMS, 128) returns a 0x06 packet with an empty data section.

Write and verification policy under test

The new tests encode these rules:
  • Capability-driven writes. Params marked RW-capable (28 of 51) may only be written via FUNC 0x03 (verified write). Plain FUNC 0x02 writes are rejected at packet-build time, before any UDP traffic. Write-only params (5: FILTER_RESET, RESET_ALARMS, FACTORY_RESET, WIFI_APPLY, WIFI_DISCARD) keep FUNC 0x02. Read-only params (18) reject every write.
  • Verified write. 0x03 + echo comparison; returns the applied values. Idempotent writes retry up to 3 attempts on timeout, then raise VentoAckError (with attempts). Invert-sentinel writes (value 2 on params defining “2 – Invert”, e.g. POWER) get a single attempt so a lost ack can never double-toggle.
  • Correlation. Acks are tied to requests by the header device ID and the transport source address; mismatches raise VentoAckMismatchError / are ignored.
  • Negative acks. VentoUnsupportedParamError gains an applied mapping so mixed acks (device applied SPEED, rejected 0x90) do not discard the applied subset.
